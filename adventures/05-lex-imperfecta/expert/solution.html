What Was Fixed

The intruder (speculator) passed admission and read the census archive undetected. Three independent defects allowed this — each required a separate fix.

1
Falco rule condition replaced Placeholder proc.name = "GUARD_NOT_YET_ACTIVE" swapped for a real syscall + path filter on /run/secrets/census-archive/.
2
Capabilities gap closed in admission policy The intruder used privileged: false + SYS_ADMIN to bypass the existing check. A second validation now blocks any capabilities.add in province containers.
3
Census archive sealed at admission New policy restrict-census-archive denies any pod mounting the census-archive secret unless it carries republic.rome/role: archivist.
4
Rename-evasion blocked The archive policy inspects volume.secret.secretName, not the volume's own name — renaming the volume cannot evade the gate.

Act 1: Falco Rule Fix

falco-rules.yaml — condition

# Before (never fires) condition: proc.name = "GUARD_NOT_YET_ACTIVE" # After condition: > evt.type in (open, openat, openat2) and evt.is_open_read = true and fd.name startswith '/run/secrets/census-archive/'

Act 2: Capabilities Validation

no-privileged-containers.yaml — added validation

- expression: >- variables.allContainers.all(c, c.?securityContext .?capabilities .?add .orValue([]) .size() == 0 ) message: "Adding Linux capabilities is not permitted in the provinces."

Act 3: Archive Policy — Core Expression

restrict-census-archive.yaml — variable + validation

variables: - name: mountsCensusArchive expression: >- object.spec.?volumes.orValue([]) .exists(v, v.?secret.?secretName .orValue('') == 'census-archive' ) validations: - expression: >- !variables.mountsCensusArchive || object.metadata.labels ['republic.rome/role'] == 'archivist'
